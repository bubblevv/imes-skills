# SYSFMA 动态公式快速路径

用于排查或调整由 `SYSFMA` 驱动的动态单据网格自动计算。`SYSFMA` 是客户端读取并执行的公式配置，不是数据库触发器；先确认目标客户端版本的实际实现，再套用以下路径。

## 运行契约

在已核对的客户端实现中，明细网格 `AfterEdit` 调用 `AutoCaculate`。事件可能在单据不可编辑、当前行尚未选物料、行/列无效或触发列类型不含 `N` 时提前返回。排查时先确认实际编辑状态、触发字段的 `v_tbcolumn` 行和事件路径。

该实现按单据名和被编辑列的字段名查询 `SYSFMA_MC`、`SYSFMA_CFX`。`SYSFMA_CFX` 必须与网格列元数据中的物理字段名完全相同，显示名不能替代字段名。公式正文再用当前行网格值替换元数据字段名；`SYSFMA_MDX` 必须能在当前字段记录集中解析到回写列。检查触发列类型、回写列类型及精度，不能从显示标签推断。

注意查询谓词是否包含 `SYSFMA_PO`。有的客户端实现只按 `SYSFMA_MC` 和 `SYSFMA_CFX` 查找；如果相同字段名跨 PO 配了多条规则，不能假定 `PO` 会在运行时自动隔离它们，必须对照当前客户端源码确认。

公式最终以 `SELECT ROUND(<公式>, <精度>)` 交给 SQL Server 执行，然后写回当前行。错误处理可能捕获数据库异常而不提示，所以“规则存在”不等于“公式成功”。验证应同时检查字段替换后的 SQL、公式单独试算和真实客户端事件。

对源码已确认每次 `AutoCaculate` 都直接查询 `SYSFMA` 的版本，不要仅凭表单初始化时另有缓存就判断需要重开窗口；核对当前运行客户端的代码路径。若仍无回写，检查事件提前返回、触发字段元数据、匹配的 `SYSFMA` 行和公式执行错误。

## 公式口径与变更

先区分以下两种策略：

- 仅在结果列为空或为 0 时补算，保留现有非零数量。
- 有效输入变化后始终重算，即使会覆盖已有非零数量。

两者只差公式条件，却会改变用户已经手工调整的数量。先用只读查询统计有效输入区间与当前结果不一致的行，并确认业务期望；没有明确确认时保留现有结果值的保护条件。边界输入（空值、0、结束值小于起始值、相等、已有非零结果）都应纳入试算。

执行配置变更前：

1. 查询并记录目标规则的完整旧值，确认 `SYSFMA_MC`、`PO`、`BH`、`CFX`、`MDX`、`FXBZ` 和公式正文，检查触发列是否有重复或冲突规则。
2. 对照 `v_tbcolumn` 或对应字段元数据，验证触发字段和回写字段都存在于同一单据明细，类型和顺序符合客户端实现。
3. 检查公式存储列容量，预览新旧公式并用样例输入在 SQL Server 上试算。
4. 仅更新已确认的规则行；使用目标身份保护、旧值谓词、事务和精确影响行数断言。准备可恢复旧公式的补偿语句，更新后重新查询完整规则行。
5. 不把配置更新误当成批量回算。`SYSFMA` 变更只影响之后实际触发公式的网格行；业务数据是否修改要单独授权和验证。

数据库公式试算通过后，仍需分别报告真实客户端验收状态。至少验证有效区间、原结果非零时的策略、无效区间保留行为，以及只影响当前编辑行这一范围。
