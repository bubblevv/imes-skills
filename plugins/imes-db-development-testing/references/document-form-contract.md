# 动态单据的数据库契约

## 适用范围

当用户要求新增调拨单、出入库单、转移单或其他由元数据驱动的 iMES 单据时，先读本文件，再读 `references/schema-development.md`。本文件只定义数据库对象、元数据和只读验收；不创建 MFC 类、对话框资源、菜单资源或修改客户端源码。

“建表并注册”只有在下面的数据库契约全部闭合后才算完成。客户端能否显示图标、命令 ID 或实际控件仍属于客户端边界，但数据库交付必须让现有动态单据引擎能够解析出表、字段、关联和权限。

## 源码证据与边界

下列是当前工程源码确认的读取路径。它们说明运行时依赖，不能替代目标数据库的实际表结构；字段类型、默认值和业务含义仍须在目标库中用 `sys.columns`、对象定义和数据确认。

| 源码入口 | 数据库行为 | 开发含义 |
|---|---|---|
| `MainFrm.cpp::CMainFrame::AutoOpen` | 先按可见名查 `IOBDZD_MC`，只有未命中有效 `IOBDZD_MARK` 时才回退查询 `IOJCBDZD_BTYPE` | 同名表单若注册了有效 `IOBDZD`，运行时进入动态单据；`BTYPE=2` 不能替代统一单号的表头/明细业务单据 |
| `Bill.cpp::CBill::InitForm` | 按 `IOBDZD_MC` 读取 `IOBDZD_HTABLE`、`IOBDZD_FTABLE`、`IOBDZD_BH`、`IOBDZD_TAB1..3`；再按单据名读取 `v_tbcolumn`，并按 `PO` 分出表头/明细；同时加载启用的 `BDJB` | `IOBDZD`、有效的 `v_tbcolumn` 元数据和单据类型对应的 `BDJB` 是动态单据的最小运行契约 |
| `Bill.cpp::CBill::OnSize`、`SGSoft.cpp::MoveToItemSJ/MoveToItem/MoveToMid` | 窗体调整大小时把制单人、审核人、摘要按固定页脚关系重排，并以审核控件与制单人控件之间的区域放置页签 | `ZDR/SHR/ZY` 是固定布局锚点，`SHBZ` 的矩形底边是非固定表头区域的下限；数据库默认坐标不能把这些字段当普通自定义槽位 |
| `BillForm.cpp::CBillForm::OnCreate`、`ReportChAccountBill.cpp::InitForm` | 标准动态单据同时创建“表单维护”和“单据查找”页；查找页固定按 `<IOBDZD_MC>查询` 调用 `GetDataField`/`LoadGridSet`，但仍按原 `IOBDZD_MC` 调用 `GetCrossTable` | 除维护用 `PO=1/2/...` 外，还必须注册独立查询字段集；缺失时会生成 `SELECT  FROM ...` 并在标题栏初始化时报 `from` 附近语法错误 |
| `SGSoft.cpp::GetCrossTable` | 优先使用 `IOBDZD` 主表/明细表和主外键；没有时回退 `IOPOPDLG_JOINSTR`，再回退 `IOJCBDZD_TABLE`；随后依据 `v_tbcolumn` 中的 `GLZD`、`LMark`、`RMark`、字段名和 `IOJCBDZD_VKEY` 拼接左连接；旧客户端捕获 ADO/元数据异常后返回空字符串 | 参照查询不只依赖物理表；每个需要翻译或连接的列都必须有完整的关联元数据。`IOBDZD` 存在不等于最终 `FROM` 可用，必须单独验证交叉表结果 |
| `SGSoft.cpp::GetCrossTableS` | 与 `GetCrossTable` 类似，但按 `PO=1` 构造简化参照查询，并可使用 `IOPOPDLG_HTABLE` | `CZ` 与 `CZD` 的来源表/列范围不能混用，必须分别验证 |
| `SGSoft.cpp::Quotebill`、`Bill.cpp::Quotebill` | 按当前单据和操作名读取启用的 `IOYYGX`；用 `IOYYGX_GLTJ` 替换当前表头/分录值；`CZ` 调用完整参照，`CZD` 调用简化参照；红蓝业务还按 `IOYYGX_HZBZ` 过滤 | 参照行必须是唯一、启用且能解析过滤占位符的配置；红蓝分支要成对检查 |
| `SearchRelation.cpp::CSearchRelation::LoadData` | 对启用的 `IOYYGX` 执行 `SYLJ`、`XYLJ`，替换 `@SJDH`、`@FLH` 后以 `UNION ALL` 汇总上下游单据 | 上下游 SQL 必须是可执行的单一查询，并返回搜索窗口实际需要的列集，不能夹带调试结果集 |
| `WorkspaceBar*.cpp`、`MainFrm.cpp`、`SysAuthority.cpp` | 按 `SYSWSPACE_LOC`、`SYSWSPACE_BH` 层级、`SYSWSPACE_BTN=0`、`SYSWSPACE_MX=1` 和当前角色列加载叶节点；权限界面直接读取/更新角色列 | `SYSWSPACE` 的层级、叶节点和角色列必须同时正确；仅插入一行但没有父节点、角色列或有效命令映射不算开放成功 |

如果活动客户端版本与上述入口不同，先从活动源码确认实际查询，再更新本地项目知识；不要把本表中的字段名直接当成所有部署的固定 schema。

### 三种表单路径必须先分型

在建表前依据 ER 图、用户描述的运行行为和相邻源码对象区分以下三条路径。用户说“两个表单”不等于只能创建两张物理表；一个表单可能由表头和多个明细表组成。

**`BTYPE=1` / `UForm1` 单表：**

- `IOJCBDZD_MC` 是唯一可见表单名，`TABLE`、`VKEY`、`BYZD` 指向同一张真实表；`SYS_TbColumn.表名` 使用同一个可见名；
- `UForm1` 从主键字段第一个下划线前推导物理表名，故表名使用无下划线兼容前缀，字段统一为 `<TABLE>_*`；
- 适用于点检项目、单位、状态等一行即完整表达的基础资料。

**`BTYPE=2` / `UForm2` 分类树 + 右侧数据集：**

- `IOJCBDZD_MC` 和 `TABLE` 表示右侧明细表单/明细物理表；`LBTABLE` 和 `LBNAME` 表示左侧主表树的物理表/元数据名；
- 主表必须具备 `<MASTER>_BH`、`<MASTER>_MC`、`<MASTER>_PBH`。`BH` 是客户端选择和删除使用的唯一单列键；复合业务键不能直接替代它；
- 明细表必须具备 `<DETAIL>_ID`、`<DETAIL>_BH`、`<DETAIL>_LBBH`。`UForm2` 用 `LBBH=<MASTER>_BH` 过滤明细，用 `DETAIL_ID` 删除行，并读取 `DETAIL_BH` 判断主表是否已有明细；
- 明细 `LBBH` 元数据通常位于顺序 1，并通过 `切换=1`、`GLZD=<MASTER>_BH` 显示主表名称、保存主表键；主表和明细分别使用 `LBNAME` 与 `MC` 两套 `SYS_TbColumn.表名`；
- 这是目录选择后维护右侧数据集的基础资料界面，不是一个统一单号下的表头/分录保存单元，也不使用同一表单名的 `PO=1/2/3` 组织页签；只有业务确实是分类树时才选它。

### BTYPE=2 的运行时硬字段门禁

`UForm2` 的左侧树和右侧数据集不是完全动态的字段集合。活动源码必须先形成并保存以下硬字段契约：

```text
树表：<MASTER>_PBH、<MASTER>_BH、<MASTER>_MC
明细表：<DETAIL>_ID、<DETAIL>_BH、<DETAIL>_LBBH
```

`*_CODE`、`*_NAME`、中文标签、帮助路由或 `IOJCBDZD_VKEY/BYZD` 都不能替代这些源码直接读取的物理列。建表前同时检查源码、`IOJCBDZD` 路由、`sys.columns`、两套 `SYS_TbColumn/v_tbcolumn` 字段和生成 SQL；必须执行树根查询及选中节点的明细查询。任一命名不一致、硬列缺失、字段列表为空或筛选列不可执行，都必须在 DDL/元数据写入前阻断。

**`IOBDZD` / 动态主从单据：**

- 一个可见 `IOBDZD_MC` 对应表头 `HTABLE`、首个明细 `FTABLE`、主外连接键和页签名；同一可见名下的 `SYS_TbColumn.PO=1` 是表头，`PO=2/3/...` 是明细表或页签；
- 表头、各明细共享一个 `_SJDH` 单号并由保存、删除、审核/取消审核作为一个业务单元处理；
- 只要用户要求统一单号的模板头与多行项目、审核/取消审核、业务单据参照或上下游关系，就必须选此路径，不得因为只有两张业务表而改用 `BTYPE=2`；
- `AutoOpen` 需要非空且唯一的 `IOBDZD_MARK` 才会进入此路径；必须确认 `MC/BH/MARK` 均无冲突。

前两种基础资料路径通常不要求 `IOBDZD`、`IOYYGX`、`IOPOPDLG` 或 `BDJB`。动态单据则必须闭合 `IOBDZD`、同一表单名的 `PO` 元数据、客户端实际要求的 `BDJB`、表单和操作权限，以及标准 `sysmenu` 按钮集；`IOYYGX`/`IOPOPDLG` 仅在确有参照或上下游消费者时配置。

## 完整数据库流程

### 1. 先写单据契约

在建表前记录并从相邻单据证明：

- 单据显示名、`IOBDZD_BH`、`IOBDZD_MARK`、非空 `IOBDZD_FORMAT`、主表和明细表名称；新建契约未提供格式时默认为 `YYMM####`，不能写入 `NULL`、空字符串或空格；
- `IOBDZD_BH` 和 `IOBDZD_MARK` 必须先勘察后分配，不能逐张表单临时编：先只读盘点目标库现有 `IOBDZD`，按业务类归组，再从盘点结果推出两个值。`IOBDZD_BH` 是稳定的类代码，同类表单集中排列，按“类前缀 + 序列号”取该类当前最小未用序号；已确认的类前缀必须沿用，不得为已归属某类的表单另造前缀、重排无关路由或凭单张表单孤立取号。`IOBDZD_MARK` 是单号前缀，必须恰好两个 ASCII 英文字母且在整张 `IOBDZD` 中全局唯一；`NULL`、空串、空白、数字、中文、三个及以上字母、混合非 ASCII 和重复值一律拒绝。两者都是固定路由标识，修复时不得为迁就新表单而改动既有已确认值；
- 对 `CBill` 路线，表头固定字段卡为 HID（`<HEADER>_ID`）、日期（`<HEADER>_YWRQ`）、凭证类型（`<HEADER>_PJLX`）、单号（`<HEADER>_SJDH`）、打印次数（`<HEADER>_PRINT`）、审核（`<HEADER>_SHBZ`）、制单人（`<HEADER>_ZDR`）、审核人（`<HEADER>_SHR`）、摘要（`<HEADER>_ZY`）；每个字段必须同时有真实物理列和 `PO=1` 维护元数据。物理日期字段必须为 `类型=D / 控件=E`。`PJLX` 物理列必填且保存 `IOBDZD_BH`，维护页和查询页元数据必须为 `类型=S / 控件=S`，并满足 `必填=1/切换=1/GLZD=IOBDZD_BH`；标准审核状态映射为 `切换=1/GLZD=LSDJZT_BH`。`审核(<HEADER>_SHBZ)` 必须为 `类型=S / 控件=E` 的普通编辑框（默认值通常 `0`，物理列可为 `bit NOT NULL DEFAULT 0`），通过 `GLZD=LSDJZT_BH` 显示审核状态字典（未审核/已审核等）；**不得**误写成 `类型=C / 控件=C` 复选框，`必填` 必须为 `0`，维护页 `只读=1`（状态由审核/撤审流程写入）、查询页 `只读=0`（作为筛选列），`列宽` 与同版本参照一致。除日期和 `*_PJLX` 外，新生成字段固定 `控件=E`、`类型=S`，不得自行豁免；字段后缀或映射不同必须由活动源码证明，不能自行豁免；
- 每个动态明细页的固定字段卡为 FID（`<DETAIL>_ID`）、单号（`<DETAIL>_SJDH`）和分录号（`<DETAIL>_FLH`）；
- 主表到明细表的连接键、明细行号、数量/金额精度、仓库/物料/批号等业务键；
- 新增、修改、查询、审核、反审核、红蓝或调拨方向的拥有者；是否需要 `BDJB`、库存校验、上下游回写和同步；
- `IOBDZD_TAB1..3` 对应的页签、`PO` 分组和每个字段的显示名/物理名映射。

把“已从源码/目标库确认”和“本次拟定”分开记录。任何无法证明的字段意义、状态值或数量公式保持 unknown。

先列出每个业务对象的基数：独立基础资料、主表 1:N 明细、单据头 1:N 分录、还是多对多桥表。若 ER 图已有 `TEMPLATE` 与 `TEMPLATE_ITEM`，不得把模板头作为完整单表交付；若客户端选择键只能是单列，还要把版本复合键转换为独立稳定键或明确客户端不兼容。

### 2. 建物理表和字段

按 `schema-development.md` 先检查同类单据，再创建主表、明细表、键、约束和必要索引。特别验证：

- `IOBDZD` 指向的每个表真实存在，主表/明细表连接字段类型、长度和字符集兼容；
- 动态保存路径需要的字段都是真实列，不能只在 `SYS_TbColumn` 中登记；
- 主键、业务单号和明细行号的唯一性符合现有编号策略；
- 默认值、非空、精度和状态初值不会使动态 INSERT/UPDATE 生成非法 SQL；
- 审核/反审核、库存、上下游和同步规则所需的列在测试库中均可读写（只在获得明确写授权的测试环境执行写测试）。

### 3. 注册 `IOBDZD`

以目标库实际列为准，至少闭合以下映射：

| 配置 | 验收 |
|---|---|
| `IOBDZD_MC` | 与 `v_tbcolumn.表名`、客户端传入的业务显示名和 `IOYYGX_BDMC` 一致且唯一 |
| `IOBDZD_BH` | 稳定类代码；当前动态引擎把它写入表头 `<HEADER>_PJLX` 并用于数据权限/固定过滤。不要假设它等于可见名。同类表单集中排列，按“类前缀 + 序列号”取该类当前最小未用序号；分配前必须只读盘点现有 `IOBDZD` 并按业务类归组，不得逐张表单孤立取号。前缀加序列号后长度不固定，依赖它的列宽按当前最长路由值计算，不要按固定六字符估算 |
| `IOBDZD_MARK` | 单号前缀；`PRD_GETDANHAO` 按 `IOBDZD_MC` 读取该值后拼接单号。必须恰好两个 ASCII 英文字母且在整张 `IOBDZD` 中全局唯一；`NULL`、空串、空白、数字、中文、三个及以上字母、混合非 ASCII 和重复值一律拒绝。取值优先用该单据区别性名称的拼音首字母（`点检模板`→`MB`、`维修工单`→`WX`、`资产入库单`→`RK`）；凑不出可读缩写时，任取一个未占用的两字母组合即可。唯一性是硬约束，好记只是偏好，不得为了保住更好看的缩写而复用已占用的 MARK |
| `IOBDZD_HTABLE` / `IOBDZD_FTABLE` | 分别指向真实主表/明细表；没有明细时确认客户端是否允许为空，不能照抄其他单据 |
| `IOBDZD_TAB1..3` | 只有存在对应 `PO` 页签时才配置；验证空页签不会让客户端生成错误过滤 |
| `IOBDZD_HVKEY` / `IOBDZD_FVKEY` | 当引擎用主外键拼接参照时必须能在两张表中解析 |
| `IOBDZD_AVBKEY`、`IOBDZD_IOFLAG`、`IOBDZD_TYPE`、`IOBDZD_MANUAL`、`IOBDZD_AFFSTOCK`、`IOBDZD_SLZD`、`IOBDZD_SUM` 等 | 仅在该版本源码读取且业务需要时配置；逐项检查枚举值和消费入口，不因名称相似而猜默认值 |

验证 `MC`、`BH`、`MARK`、主表/明细表映射不存在重复和悬空引用，并以一条只读查询证明每个值能被按运行时查找键取回。`MARK` 额外断言形状（长度为 `2` 且不含 `[A-Za-z]` 之外的字符）与全表唯一；`BH` 断言在同类中不重复。当前 `GenDanhao` 传入 `IOBDZD_MC`，`PRD_GETDANHAO` 也按 `MC` 读取 `MARK/FORMAT/BascData/CurMonth/ModifyDate` 并更新编号状态；`BILLNO` 不是该入口的格式来源。对新建的 `YYMM####` 路由，按已确认的过程语义初始化 `BascData=0`、`CurMonth=CONVERT(varchar(7),GETDATE(),111)`、`ModifyDate=CONVERT(date,GETDATE())`，不能留空，否则首个流水号会跳过有效分支；同时显式写入已确认的 `IOBDZD_Type` 与 `IOBDZD_IoFlag`。确认过程定义支持的格式分支后再接受非默认值；存量修复先断言空值分布，只更新精确目标行，不重置已有计数状态。

### 4. 注册 `IOJCBDZD` 和字段帮助

`IOJCBDZD` 在源码中有两种用途，不能只注册其中一种：

1. **业务/表参照映射**：按 `IOJCBDZD_MC` 或实际业务键查出 `IOJCBDZD_TABLE`、`IOJCBDZD_VKEY`、`IOJCBDZD_BYZD`、`IOJCBDZD_FILTER`。用于生成 INSERT/UPDATE 的显示值到主键转换，以及 `GetCrossTable` 的连接。
2. **字段帮助/选择器**：`SYS_TbColumn` 的 `帮助` 值必须能在 `IOJCBDZD_BZBH` 中唯一找到对应 `BZMC`、表、键、显示字段、过滤条件；树形或物料选择还可能需要 `LBTABLE`、`JSZD`、`SXXS`、`BTYPE` 等实际列。

对每个启用了 `切换=1` 或 `帮助` 的字段，做双向只读验证：显示值能查到存储键，存储键能反查显示值，过滤条件为空/有值时都能执行，且没有多行歧义。`VKEY`、`BYZD`、过滤条件中的所有表列必须存在；不要把显示名列误当主键列。

### 4.1 `GetCrossTable` 交叉表闭合

`GetCrossTable(<IOBDZD_MC>)` 是旧客户端的脆弱入口：其 ADO/元数据异常会被捕获并转换为空字符串。验证时必须把 `GetDataField(<MC>查询)` 和 `GetCrossTable(<MC>)` 分成两个结果分别断言，不能因为 `IOBDZD` 路由存在或查询字段非空，就跳过 `FROM` 来源检查。

对每个 `v_tbcolumn` 中 `GLZD` 非空的字段，必须闭合以下值：业务侧 `字段名`、`IOJCBDZD_TABLE`、`IOJCBDZD_VKEY` 与别名组合；当该行 `切换=1` 走显示值转换时还必须闭合 `IOJCBDZD_BYZD`。`LMark` 是关联表左侧别名、`RMark` 是业务表/右侧来源别名：有 `LMark` 时源码生成 `LEFT JOIN <关联表> AS <LMark> ON <RMark>.<字段名>=<LMark>.<关联键>`；`LMark` 为空时关联表无别名，并以 `RMark`（若有）限定业务字段。空别名是合法值，必须写空字符串而非 `NULL`；有值时必须实际出现在表或列引用中。`GLZD` 非空行负责建 JOIN；其中 `切换=1` 的编号输入行还会由 `GetDataField` 输出 `LMark.IOJCBDZD_BYZD`，而 `GLZD=''`、`RMark` 非空的关联显示行则输出 `RMark.字段名`。不得把编号字段、关联显示字段或别名关系当作可随意改名的界面文案。然后按源码优先级依次验证 `IOBDZD` 主从键、`IOPOPDLG_JOINSTR` 回退和 `IOJCBDZD_TABLE` 回退，执行生成的每一条 `LEFT JOIN`。

标题 SQL 至少执行两种故障断言：`SELECT  FROM <有效交叉表>` 表示查询字段集为空；`SELECT <非空字段集> FROM )` 表示 `GetCrossTable` 为空或其关联拼接失败。任一结果都必须阻断交付，不得只补查询页字段或用客户端空指针保护掩盖元数据错误。

### 5. 设置 `SYS_TbColumn`，用 `v_tbcolumn` 验收

客户端读取的是 `v_tbcolumn`，不是未经确认的裸元数据行。先检查视图定义和它依赖的 `SYS_TbColumn`、`sys.columns`、`IOJCBDZD`，再登记字段。

对每个表头/明细字段核对实际存在的属性（名称以目标视图为准）：

- 物理 `字段名`、`显示名`、`类型`、`顺序`、`PO`、`RID`；
- 动态表头的 `标签名`、`控件`、`左坐标`、`顶坐标`、`宽度`、`高度`；
- `主键`、`必填`、`新增`、`更新`、`显示`、`只读`；
- `帮助`、`切换`、`GLZD`、`LMark`、`RMark`、`标识`；
- 视图派生的 `IOJCBDZD_TABLE`、`IOJCBDZD_VKEY`、`IOJCBDZD_BYZD` 和其他转译列。

当前动态表头创建路径会把 `类型`、`字段名`、`标签名`、`控件` 直接转换为字符串，并把 `RID`、`顺序` 及显示/必填/只读等标志直接转换为运行值；这些列不是可省略的外观配置。尤其每个 `PO=1` 行（包括隐藏的 ID 行）都必须有非空且有效的 `控件`。`顺序`必须在每个 `(表名,PO)` 内编译后重排为从 `1` 开始的连续序列，不能保留 `0`、空值、重复或跨 `PO` 复用的序号。`RID` 是运行时控件 ID，维护页和独立查询页都必须为正整数，并在本次新增元数据集合内唯一；新部署应在事务内按目标库当前 `MAX(RID)+offset` 分配，不能写死另一个客户或环境的 RID。新生成元数据中，物理 `date`、`datetime`、`datetime2` 字段使用 `类型=D`，其余字段使用 `类型=S`；普通字段的控件为 `E`，`*_PJLX`/凭证类型字段的控件为 `S`。存量修复若确有同版本源码证据，才可在单独的逐字段修复契约中保留非默认控件。所有表头行应有非空 `RID`、`类型`、`标签名`、布尔/枚举标志和布局值，可见控件还须有正数宽高。修复存量元数据时先断言完整字段集合和当前空值分布，再在事务中按逐字段映射更新，禁止用一个默认值无条件覆盖全部控件类型。

在生成前，`preflight.sql` 必须对固定字段卡逐项查询 `sys.columns` 和 `v_tbcolumn`；任一物理列、`PO` 元数据、`PJLX` 映射、`SHBZ` 映射或明细 `FID/单号/分录号` 缺失即 `THROW`，不得用补一条孤立元数据或客户端空指针保护掩盖不完整契约。

动态业务单据源码按 `PO=1` 取表头、按 `PO>1` 取明细/页签；`UForm2` 分类树路径则按 `LBNAME` 与 `MC` 两套表名分别加载左右元数据，不能用同一 `PO` 集合冒充。两者都按 `顺序` 生成控件和 SELECT 字段；当 `切换=1` 时使用 `IOJCBDZD_VKEY` 作为有效字段。验收必须证明：

- 每个 `字段名` 只映射一个真实列，`顺序` 在每个 `(表名,PO)` 内必须是 `1..COUNT(*)` 且无间断/重复；显示名和顺序在同一 `PO` 内不冲突；
- 主键字段有可用的 `主键=1`、更新路径能构造唯一 WHERE；
- 必填/只读/新增/更新标志与物理列可空性和业务操作一致；
- 每个动态表头 `PO=1` 行的 `控件` 非空；`*_PJLX` 为 `S`，其他字段为 `E`；新生成维护页和查询页中物理日期字段的 `类型` 为 `D`，其他字段为 `S`；维护页和查询页 `RID` 非空、为正数且集合内唯一，`标签名/标志/布局` 完整；
- `GLZD` 非空的字段同时具备关联表、业务字段和关联键；`LMark/RMark` 为源码形状所需的已证明别名或显式空字符串，所有左连接实际可执行；编号输入行和关联显示行均有可解析的投影；
- 新生成元数据只按已确认的物理日期类型生成 `类型='D'`，其余字段为 `类型='S'`；存量数据分析时可以记录目标库现值，但不能把 `N/C` 或其他未证明类型自由带入新的生成契约；
- 生成的表头、明细和参照 SELECT 均只有一个结果集，列名与报表/PDA/同步消费者保持兼容。

对动态单据的每个 `PO>1` 页签还要验证当前 `PageRowsTab` 的硬契约：顺序 1 的字段名前缀能推导真实物理表；存在显示名 `FID`、`单号` 和通常需要的 `分录号`；至少一个实际业务输入字段设置 `关键字段=1`，不能把自动回填的单号/分录号当作行存在标志；`<DETAIL>_ID` 可唯一删除一行，`<DETAIL>_SJDH` 可定位整单明细。

### 5.1 主表自定义字段的默认坐标

主表自定义字段的坐标、宽度和高度必须从同版本可正常打开、布局等价的表头单据生成。先读取参考单据 `PO=1` 的可见矩形和 `Bill.cpp::CBill::OnSize` 的运行时重排逻辑，再生成目标字段布局：

1. 隐藏 `HID` 等身份字段的坐标和尺寸全部为 0。
2. `ZDR`（制单人）、`SHR`（审核人）、`ZY`（摘要）是固定页脚锚点，必须逐项复制参考字段的 `左坐标/顶坐标/宽度/高度/列宽` 和控件契约，不能作为自定义字段槽位，也不能因为其他字段换行而移动。同类单据的通用摘要通常为 `E`、单行参考高度；只有源码明确要求长文本时才使用 `EM` 并自适应高度，不能默认把摘要改成 `EM`。
3. `SHBZ`（审核）是表头下限锚点，不是必须独占的一栏。把它和可见表头字段放入同一横向装箱过程：先尝试当前行，只有完整占用区超过参考右边界才换到下一行。以 `SHBZ.顶坐标 + SHBZ.高度` 计算 `headerLowerBound`；所有非固定表头字段的底边必须不超过该下限。审核换行时，才用上一行最后一个非固定可见字段底边加参考自然间距推导审核顶边；审核同行时不要求虚构的垂直 gap。
4. 日期、凭证类型、单号等语义锚点先按确认的字段意义绑定；每一行第一个普通输入框的 `左坐标` 必须等于参考单据同类可见字段的最小 `左坐标`，不为字段数量另设新左边距。后续字段不使用固定 X 坐标：客户端 `CDataEdit::OnSize` 以 `GetTextExtentExPoint(标签名)+6` 创建标签，并将标签放在输入框左侧 5 个单位处，因此下一个输入框的左边必须按“前一输入框外框右边界 + 参考视觉间隔 + 下一标签实测宽度 + 5”计算。字段带非空 `帮助` 时，`CBCGPEdit` 的浏览按钮还会占用非客户区宽度；当前版本 `EnableBrowseButton(true)` 默认 `m_nBrowseButtonWidth=20`，自定义图标按 `max(20,imageWidth+8)`，若契约按文本区给宽度，必须先加该实测按钮宽度得到输入框外框宽度。实测标签和按钮值必须来自同版本客户端、同字体和 DPI；不能以汉字个数、固定每字像素数或网格列宽估算。无法取得实测值时，交付为审阅阻断包，不得宣称无重叠。
5. 按字段 `顺序` 逐项装箱，优先保留当前行的剩余空间；只有下一字段的完整占用区（标签、标签/输入框间距、输入框外框、帮助按钮占用和右侧余量）放不下时才换行。换行行首回到参考最左坐标，不能随前行残余空间漂移。字段减少时可回收审核顶边，不能保留旧表单的大空洞；字段增加或帮助按钮使占用变宽时，只重排非固定字段和审核行，不移动 `ZDR/SHR/ZY` 固定页脚。
6. 新字段中物理 `date`、`datetime`、`datetime2` 使用 `类型='D'`；普通字段控件为 `E`，`*_PJLX`/凭证类型字段控件为 `S`。通用硬字段只使用源码/表结构证明过的默认值（例如版本初值 `1`、审核初值 `0`；日期、制单人、单号由客户端/编号路径初始化），不要为源码忽略 `默认值` 的字段发明占位符；非通用字段无业务证明时保持空值。`EM` 多行字段可以在参考高度基础上自适应增加高度，但必须只重排非固定行，并重新检查审核下限和矩形交叠；日期、参照、状态和普通文本优先继承相同类型的参考尺寸。
7. 验收必须检查：固定锚点、控件代码和通用高度与参考完全一致；非固定字段按 `(顶坐标,左坐标,顺序)` 排序；每个输入框连同实测左侧标签、帮助按钮占用区不与同排前一控件重叠；`SHBZ` 在当前行可容纳时必须同行，换行时才检查上一行到它的自然间距；每个首字段左坐标均等于参考最左值；非固定字段底边不超过 `headerLowerBound`；可见字段尺寸为正、坐标在参考画布内、同一 `PO` 的可见矩形不相交、`列宽` 非空。`<单据名>查询` 是网格字段集，通常使用零坐标，不能把查询坐标当成维护页坐标。

布局生成应输出目标字段到参考字段/槽位的映射，作为 forward、rollback 和 verification 的一部分；这样修改字段顺序或重复执行脚本时不会产生漂移。

### 5.2 注册独立的动态单据查询字段集

标准 `CBillForm` 不只加载维护页，还会初始化 `CReportChAccountBill` 查询页。查询元数据的可见名固定是 `<IOBDZD_MC>查询`；它不是另一个 `IOBDZD`，也不能用原单据名的 `PO=1/2` 行自动替代。查询页从该名称生成字段列表和网格设置，但 FROM/JOIN 仍来自原单据名的 `GetCrossTable`。 查询页字段集本身必须落在单一 `PO=1` 分组，`表头=0`，`顺序` 1..n 连续唯一，`显示名`/`标签名` 不得重复。

按同版本可用单据确认查询字段后，至少验证：

- 查询名称在 `v_tbcolumn` 中返回非空字段集，并且每个字段映射到原表头、明细或已闭合的参照表；
- 标准动态单据查询页必须保留且仅保留一个可见必填的表头单号（`<HEADER>_SJDH`，显示别名 `单号`）和一个可见必填的表头日期（`<HEADER>_YWRQ`，显示别名 `日期`）。二者是定位、筛选、默认排序和分页稳定锚点，必须实际出现在查询字段列表中；不能用明细单号、创建时间或其他同义列替代，也不能因去重删除。只有活动源码证明非标准查询入口时，才能使用该入口的固定字段契约；
- 表头单号与明细单号等同义字段只保留一个显示别名；派生表内任意 `显示名` 重复都会导致后续分页/筛选包装查询失败；
- `HID/FID`、单号、凭证类型和业务筛选字段满足查询页分页、定位和过滤入口；表头/明细 `PO` 可沿用相邻单据约定，但不能假设查询页只读取某一个 `PO`；
- `切换/GLZD/LMark/RMark` 在查询字段集中同样能解析显示列，查询页使用的控件、类型、列宽、显示和筛选属性完整；
- `列宽` 首先保证该行 `标签名` 完整可见，不以 `100` 默认回退值或参考单据的内容宽度代替字段名宽度。当前客户端以 `分录号=840` 作为 3 个汉字基准，4 个汉字的最小列宽为 `1125`；统一使用 `scripts/metadata_width.py`，ASCII 按半宽单元计算并按 `15` 单位向上取整。新建元数据未明确指定时按标签宽度生成，明确更宽时保留，明确更窄时必须阻断；静态 SQL 验证器必须复用同一规则。表格列宽使用独立的 `column_width` 契约字段，不能把表单控件布局 `宽度` 混作列宽；维护页和查询页分别计算。
- 用查询字段列表与原单据 `GetCrossTable` 拼出客户端同形的 `SELECT <fields> FROM <cross-table> WHERE 1=2` 并执行；再放入实际分页/计数所用的派生表包装，确认字段列表非空、别名唯一且 SQL 可解析。

不要原样复制全部维护元数据：明细 `_SJDH` 常与表头 `_SJDH` 同时显示为“单号”，必须按查询业务粒度去重。也不要为 `<单据名>查询` 新增伪造的 `IOBDZD` 行；它是原动态单据的附属查询字段契约。

### 6. 配置额外功能、参照和上下游

#### `IOYYGX`

每项配置先确认当前版本实际列和唯一键，再检查：

- `IOYYGX_BDMC` 指向已存在的 `IOBDZD_MC`；`IOYYGX_CZMC` 在同一单据内唯一且是用户可触发的操作名；
- `IOYYGX_YXBZ=1` 才会进入源码中明确过滤该列的动态菜单/上下游查询；逐一检查静态命令和其他入口，确保停用行不会被活动操作名选中；
- `IOYYGX_CZLX` 的 `CZ`、`CZD`、`CX` 等值与源码分支一致，不能以“参照”文字替代枚举；
- `IOYYGX_TABLE`/`IOYYGX_FROMTABLE` 的来源对象、`IOPOPDLG` 回退对象和 `IOJCBDZD` 映射能闭合；当前源码有读取列名差异时，必须以实际视图/查询结果验证；
- `IOYYGX_GLTJ` 中每个占位符都能从当前表头/分录替换，替换后是安全、可执行的 WHERE 片段；
- 需要红蓝区分的单据，`IOYYGX_HZBZ` 的活动行按 `IOBDZD_IOFLAG` 分支可唯一命中，正向和红字行都测试；
- 上游/下游关系的 `IOYYGX_SYLJ`、`IOYYGX_XYLJ`（如目标库存在）在替换 `@SJDH`、`@FLH` 后各返回预期列，使用 `UNION ALL` 时列数、顺序和类型一致，不含 `DECLARE`、临时表或调试 SELECT。当前 `SearchRelation.cpp` 的上游窗口是七列（单号、日期、单据类型、制单人、总量、达成、审核），下游窗口是六列（单号、日期、单据类型、制单人、达成、审核）；`IOYYGX_BDMC` 是当前/下游单据，`IOYYGX_CZMC` 是来源/上游单据，分别消费 `SYLJ` 和 `XYLJ`。

上下游不是参照过滤的传递链。若当前单据保存两个或多个已确认的来源单号，必须为每个直接来源分别配置 reciprocal 关系行，并分别验证两侧 SQL；不能只配当前单据到来源 A，再期待客户端沿 A 的下游关系自动找到来源 B。数据库修复必须先对目标旧行做精确断言，再在事务中分配非 identity 的关系编号、断言影响行数，并提供只在新值未被后续修改时生效的 rollback。

#### `IOPOPDLG`

只有在 `IOBDZD` 没有完整主/明细来源时才依赖其回退关系。验证 `IOPOPDLG_JOINSTR`、`IOPOPDLG_HTABLE` 使用的每个表、别名、键和列都存在，且与 `GetCrossTable`/`GetCrossTableS` 选择的模式一致。不要用一条能执行但返回错误粒度的 JOIN 代替主表/明细关系。

### 7. 注册单据脚本 `BDJB`

先从活动源码确认 `BDJB_PJLX` 的查找值。当前 `CBill::InitForm` 使用可见单据名 `billdata.strBissType`（即 `IOBDZD_MC`），不是 `IOBDZD_BH`，并且有效行数为 0 时直接拒绝初始化。因此动态单据必须至少有一组真实、可解释的有效 `BDJB`；不得用无操作脚本只为绕过加载检查。涉及审核、反审核、库存、数量回写、状态或同步时，把规则、执行顺序、前置/后置阶段、条件、`@SJDH`/`@USERNAME` 等占位符和正反向对称性列入同一数据库交付。按现有 BDJB 快速路径验证最小保存、审核、重复审核、反审核和适用的聚合/红蓝分支。

### 8. 开放 `SYSWSPACE` 和必需的 `sysmenu`

数据库层至少检查：

- `SYSWSPACE_BH` 沿用目标库的两位递增层级，所有父节点先存在，编号和名称不与现有节点冲突。`SYSWSPACE_MC` 是 `AutoOpen` 和权限查询使用的运行时业务名，必须与新表单的 `IOJCBDZD_MC`/`IOBDZD_MC`、`SYS_TbColumn.表名` 完全一致，并在目标库全局唯一；若通用名称（例如“物料”）已存在，必须为新路由选择业务限定名并同步所有引用，不能只修改工作区显示文字或覆盖旧节点。预检要同时检查生成内重复和目标库既有名称冲突；
- `SYSWSPACE_LOC` 使用正确的功能栏（当前源码分别按 1、2、3 加载），`SYSWSPACE_BTN=0` 才进入树，叶表单使用 `SYSWSPACE_MX=1`；
- `SYSWSPACE_JS` 与层级深度一致，当前角色列真实存在且为 1；权限查询能返回该叶节点；
- 动态单据工具栏调用 `IsValid(<单据名>,<操作名>)`，因此还要从活动菜单文字确认并建立所需操作权限行；常见操作是新增、编辑、复制、审核、取消审核、打印、打印设计和删除，权限名称通常为 `<单据名><操作名>`，不能只开放表单叶节点；
- 如果该单据依赖数据库 `sysmenu` 或自动打开映射，检查 `sysmenu_bdmc`、父子菜单、排序和操作名；不能仅插入 `SYSWSPACE` 就宣称菜单已完成；
- 每个新建 `IOBDZD` 主从单据固定插入以下 7 个按钮，并复制“销售订单”的参数：`显示关联单据(topfloor=0, submenu=0, xh=3, icon=40, pmenu=' ', trimenu=0, uid=' ')`、`保存列宽(0,1,3,0,'其他',1,' ')`、`列配置(0,1,4,0,'其他',0,' ')`、`从EXCEL导入(0,1,5,0,'其他',0,' ')`、`说明(1,0,3,24,' ',0,' ')`、`附件(0,0,3,24,' ',0,' ')`、`复制分录(1,0,3,40,' ',0,' ')`；括号内依次为 `topfloor,submenu,xh,icon,pmenu,trimenu,uid`，其中 `' '` 是销售订单数据库中实际保存的单空格值。
- 不直接复制角色列或批量覆盖已有权限。授权写入前预览目标行、角色列和父子节点，执行后只读复核。

## 只读验收矩阵

在确认的测试环境（或只读生产调查连接上只执行 SELECT）逐项记录对象、断言和结果：

1. `DB_NAME()`、`@@SERVERNAME`、兼容级别和目标版本正确。
2. 主表/明细表、主外键、业务唯一性、索引和关键运行列存在且类型兼容。
3. `IOBDZD` 的 `MC/BH/MARK -> HTABLE/FTABLE -> TAB1..3` 映射唯一，所有对象存在；`AutoOpen` 会命中 `IOBDZD` 而不是回退 `BTYPE=2`。`MARK` 为恰好两个 ASCII 英文字母且在整张 `IOBDZD` 中全局唯一；`BH` 在同类中不重复，并在证据包中记录本次分配所依据的同类盘点结果。
4. `v_tbcolumn` 的表头/明细行能按 `PO,顺序` 返回；每个元数据字段能映射物理列；维护页和查询页的 `RID` 非空、为正数且集合内唯一；每个 `PO=1` 行的控件类型和必需运行输入完整。验证 SQL 必须按 `CreateDlgItemWithArrayDateTime` 的读取形状核对 `类型/字段名/标签名/控件/显示/必填/只读/RID`，不能只查基础表行数。每个明细页满足 `FID/单号/分录号/关键字段` 和首字段表名前缀契约；连接字段和帮助映射不悬空。数据库等价验证通过后仍需真实重新打开维护页和查询页。
5. `<IOBDZD_MC>查询` 字段集非空、单一 `PO=1` 分组、无 `表头=1` 锚点行、`顺序` 1..n 连续唯一、`显示名` 与 `标签名` 各自唯一、物理/参照字段可解析，并通过与原单据交叉表拼接的标题 SQL 和派生表包装测试。
6. 每个 `切换`/`帮助` 字段执行显示值到键、键到显示值和过滤查询；每个 `GLZD` 字段执行参照 JOIN。
7. 每个活动 `IOYYGX` 操作分别执行 `GLTJ` 替换后的预览；`CZ/CZD/CX`、红蓝、上游、下游均验证。
8. `IOPOPDLG` 仅在需要时回退，JOIN 结果粒度和列集正确。
9. `BDJB` 规则按顺序、限制条件和对称反向路径检查，结果集契约无额外输出。
10. `SYSWSPACE` 父子层级、角色授权、表单叶节点、动态单据操作权限和必要 `sysmenu` 均可读回；角色未授权时对应表单或操作不可用。
11. 仅在明确授权的测试环境做最小新增/修改/审核/反审核写测试；记录影响行数、回滚和残留数据。生产只读 MCP 不得执行这些写入。

## 停止条件与交付物

遇到以下任一情况，先报告证据并停止元数据写入：`IOBDZD` 指向不存在的表、`v_tbcolumn` 有悬空字段、帮助值映射多行或无行、`GLTJ/SYLJ/XYLJ` 无法替换、`IOYYGX` 活动行冲突、父节点/角色列缺失、或无法确认 `BDJB` 的生命周期含义。

数据库交付应包含：物理表/约束/索引 forward、rollback、verification；`IOBDZD`、`IOJCBDZD`、`SYS_TbColumn`、`IOYYGX`、`IOPOPDLG`、`BDJB`、`SYSWSPACE`/`sysmenu` 的变更清单；只读验收结果；以及明确列出的客户端工作（资源、命令映射、控件或打包）待办。不得把客户端待办隐藏在数据库脚本中。
